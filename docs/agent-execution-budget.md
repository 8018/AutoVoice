# 模型与工具循环执行预算

## 范围

执行预算由 AgentLoop 启动时创建，使用 System.nanoTime。覆盖循环工作队列等待、模型调用、
工具调用、并行与重复请求缓存等待、后续模型轮次。它不是整条语音链路 SLA：不包含此前的
录音、ASR、Provider 外层队列或之后的 TTS 播放。

Classic 正数 toolLoopBudgetMs 同时作为循环总预算，默认 20 秒；0 保留“不带工具直答”
含义，直答仍有 10 秒总预算。Policy 支持显式指定独立总预算。
旧式 Qwen 音频模型/工具循环设为 45 秒总预算。连续 Realtime 闲聊会话不受此处改动影响。

## 执行规则

每轮模型调用前后检查剩余时间，过期模型结果不能再解析成导航/车控终局动作。
工具实际启动前、返回后以及等待并行/缓存结果时使用同一个截止时间。
总预算到期立即结束调用方等待、中断工作任务，并通过适配器取消该请求当前的 OkHttp Call。
没有增加“仲裁胜出取消输家”：仲裁输出资格与任务自身期限仍是不同机制。

超时走现有 Provider 异常/网关失败处理，不启动额外的模型总结，不伪造工具成功结果，
不自动忽略用户指定的途经点来执行导航。本次没有实现部分结果对话产品策略。

## 资源边界和限制

循环工作池和并行读取池各 16 个 daemon worker、64 个等待槽，超载拒绝；
排队时间包含在预算中，过期/中断请求移除未运行任务。
MCP SDK 调用通过线程中断协作终止；不保证远端工具撤销已经执行的操作。
如果 SDK 无视中断，调用方仍按时返回，后台占用受池容量限制，但槽位可能持续被占用。
完整的供应商级取消和各 MCP 请求 timeout 下传仍需对应适配器支持；不强行关闭其他请求共用的会话。

## 验证

专项覆盖慢模型忽略中断后的迟到动作拦截、串行慢工具不继续执行写操作、
并行与相同请求缓存等待期限、零工具预算的直答兼容。
同时运行 agent-loop、llm、speech-qwen-omni 和 gateway 回归。尚未生产压测或部署。
