# AutoVoice 生产化开发计划

制定日期：2026-09-11。依据：[生产架构评估](production-architecture-review-2026-09-11.md)。
初始代码基线：`a6951ec`。状态：计划已制定，以下开发任务均未实施或验收。

## 1. 目标、范围与原则

第一目标是让现有手机语音助手具备可验证的生产边界：身份不串、旧结果不污染状态、
动作不越权或盲目重试、异常请求能结束、过载可控、发布可恢复。
不整体重写，不先拆微服务，不默认引入 Redis/Kubernetes，不把真实车控认证混入手机版本交付。

必须保留评估报告第二节的全部设计约束，尤其是：

- 音频与候选并发；端侧车窗优先、云端离线空调优先，不改为先到先得。
- 仲裁器只有逐轮输出记录，没有当前轮概念；当前轮判断归会话/输出协调层。
- 落败或旧轮仅拦截输出，不取消候选计算；自身超时和资源销毁独立处理。
- VAD 不建业务轮、不直接停播；ASR 独立上屏；TTS 继续统一承接文本与音频。
- 业务 LLM 和显式闲聊 Realtime 保持域与配置隔离。

本计划只安排开发，不自动授权生产配置切换、密钥轮换、数据迁移、PR 合并或部署。

## 3. 工作包详细定义

### D01：建立生产基线

> 2026-09-11 拆分:D01a = 生产配置契约(fail-closed 启动校验);D01b = 测试夹具、
> 事件字段统一与回归场景清单。
> D01a 已完成:PR #61,`ProductionConfigGuard` + `application-production.yml`,
> classic/omni 双变体测试通过。D01b:contracts testFixtures 四夹具、
> `TelemetryFields`/`TelemetryEvent` 统一字段、`docs/production-regression-scenarios.md`。

- 范围：服务端 app 配置、CI 测试辅助设施、开发/运行文档。
- 新增独立 production 配置契约：必要身份与管理鉴权缺失时拒绝启动；保留显式本地开发模式。
  先添加契约和测试，不直接切换现有部署 profile，避免未配置凭据就造成停服。
- 建立可控制时间、Future 完成顺序、上游断连和慢下行的测试夹具；列出必须保留的行为用例。
- 为后续工作统一事件字段：主体、session、turn、request、配置版本、阶段、结果和原因。
  不记录密钥，音频/原文不作为默认诊断字段；请求 ID 不成为指标标签。
- 验收：Classic/Omni 配置校验均有测试；每个架构约束至少有明确的回归用例归属。

### D02：设备与会话身份绑定

> 2026-09-11 拆分:D02a = 服务端会话所有权与恢复凭据核心;D02b = Android 客户端
> 恢复凭据接入与协议文档。两者均已合并。
> **遗留(明确记录)**:① resumeToken 仅存客户端进程内,App 重启后丢失(重启恢复属
> D15 业务恢复协议);② 凭据轮换/吊销接口未设计(等 D03/D15 统一处理);
> ③ 过期会话的 TTL 为部署参数(默认 24h 滑动过期),未做压测定标。

- 范围：contracts、session、gateway、Android gateway-client 及协议 fixture。
- 引入认证主体和会话所有者；明确空 sessionId 新建、合法恢复、过期恢复、跨设备恢复四种结果。
- 会话恢复凭据独立于可展示的 sessionId；连接建立认证后禁止切换主体。设计凭据有效期、吊销和轮换接口。
- 旧协议只能在显式兼容环境使用；生产不能为兼容旧客户端而跳过所有者检查。
- 验收：A 不能恢复 B；错误/过期凭据拒绝；重连仍可恢复有效候选；日志不包含恢复凭据。

### D03：管理面与遥测访问控制

- 范围：telemetry、skill-manager、两个 Web 客户端及设备上传接口。
- 分离设备上传与管理员查询身份，查询/上传校验资源归属；服务凭据采用最小操作权限。
- 管理登录改为服务端随机会话，支持到期、注销和撤销；添加 cookie 安全属性、CSRF 防护及登录限流。
- 明确 HTTPS/WSS 接入配置；Android 发布配置禁用非必要明文，开发配置保留明确例外。
- 验收：上传凭据不能查询他人记录；已注销 cookie 不能重放；跨站写入被拒绝；Web 功能仍可使用。
- 上线前置：域名/证书、设备凭据发放方式确认；只开发实现不阻塞于这些部署选择。

### D04：先限制工具副作用

- 范围：ToolExecutionPolicy、RequestToolExecutor、MCP 配置校验。
- 将“读取/写入/未知”与“可并行/可缓存”分开建模。工具自报只读只能作为参考，不能替代可信配置批准。
- 生产候选阶段只执行已审核读取工具；写入和未知工具拒绝执行并给出结构化原因。
- 保留高德读取工具的并行和缓存；盘点每个实际工具，不依据名称推断是否有副作用。
- 验收：伪装只读或缺少分类的工具不能通过默认路径执行写入；llm/chat 工具隔离不回退。

### D05：导航状态只在获准采用后提交

- 范围：NavigationDialog 端口、navigation-domain、Classic/Hybrid 路由及输出协调。
- 把解析/丰富候选变为不修改共享状态的 prepare；commit 使用会话业务版本和 selectionId 条件写入。
- **不能只以云端仲裁胜出作为最终提交依据：** 端侧仍可能拦截云端结果。实施前明确端云最终采用协议，
  由当前轮所在的会话/输出协调层确认；准备记录不得覆盖已经生效的候选。
- 定义采用确认、重复确认、断线重发和未显示列表的行为；传输成功不等于 UI 已显示。
- 验收：A 晚于 B 完成不覆盖 B；端侧胜出时云端候选不激活；重复确认幂等；
  说“第一个”或地址名称只操作当前有效候选，关闭/过期/重连有一致表现。

### D06：请求生命周期统一收尾

- 范围：AgentExecutionRuntime、DeepSeek、Qwen/Hybrid 及相关回调适配器。
- 复合 RequestKey 区分主体、会话、轮次和执行请求，清除仅 utteranceId 索引造成的跨设备冲突。
- 建立统一任务登记、成功/失败/自身超时/资源关闭终态，以及排队任务被移除后的完成处理。
- 保护 sink/route 同步异常；解决提交、登记、关闭之间的竞争；按期限排空后终结剩余任务。
- 验收：排队关闭、回调抛错、重复关闭、同时登记关闭、跨设备同名轮次全部确定性完成；
  不靠固定 sleep 判断测试通过；线程数和登记数量回归基线。

### D07：建立可信动作执行边界

- 范围：contracts 的 ActionPlan/执行结果端口、工具执行路由、客户端业务执行入口及动作账本。
- 模型只能生成待执行计划；最终会话准入后再授权、校验参数/状态、执行并回报。
  对客户端动作，客户端执行入口承担最终校验；对服务端动作，需要可信采用凭据，不能让模型伪造。
- 设计稳定 actionId 和持久化幂等账本，区分待执行、执行中、成功、失败、结果未知。
- 有下游幂等键/状态查询则对接；无此能力且结果未知时禁止自动重试，不承诺严格 exactly-once。
- 验收：旧轮/落败不执行；并发重复与重启重试不盲目重复；越权被拒绝；执行结果不伪报成功。
- 首批以手机导航和模拟动作验收。真实车控约束与确认策略另行评审，未通过前保持关闭。

### D08–D09：原生引擎隔离

- D08：限制队列容量，区分“调用方超时”和“实际执行结束”；引擎失去响应后停止接收任务、显式降级。
  验收：永久阻塞不造成持续音频堆积，健康在线候选可正常完成。
- D09：核查 SDK 初始化、许可证、并发和进程重启约束后，增加独立 worker 进程、IPC、watchdog、
  重启退避和熔断恢复。没有完成核查前不指定具体进程复制数量。
- 验收：杀死/卡死 worker 不终止网关；恢复不产生旧结果污染或重启风暴；记录真实 SDK 演练证据。

### D10：预算与背压

- 范围：gateway 接入/下行、TTS 入口、Agent 预算与外部调用并发边界。
- 设置 hello 截止、每设备并发/速率、音频积压、TTS 文本长度；参数可配置并在启动时校验。
- 从请求准入建立绝对 deadline，计入排队；持续 Realtime 连接与每轮响应预算分开，不用单轮期限
  误关长期闲聊连接。
- 下行按字节有界，保证音频/控制消息顺序；定义发送超时和溢出处理，不随机丢片段维持假成功。
- 验收：慢读、无 hello、长文本、突发音频和上游退化下，资源有上界，健康设备获得服务；
  拒绝/超时是明确错误，不被统计为普通识别失败。

### D11：一致配置快照

- 范围：McpSkillRegistry、prompt stores、Agent 请求上下文、管理发布接口。
- 将工具 schema/连接、prompt、scope 和导航配置作为同一版本校验、预热、原子发布。
- 请求借用快照；旧连接按引用释放，最长退役期限与请求 deadline 对齐。Realtime 明确按会话固定
  配置还是轮边界换版，禁止在一轮中途混用版本。
- 验收：执行期间更新不破坏旧请求；新请求完整使用新版本；无效版本不覆盖已验证版本；可回退与追溯。

### D12–D13：发布与恢复

- D12：区分存活、就绪、低频业务探测；支持停止接入和有期限排空；添加最小权限账号/资源限制模板。
  常规健康探针不调用付费模型，也不因单个可降级依赖失败就无条件摘掉所有业务。
- D13：CI 输出不可变产物与摘要，部署提升对应产物；手动/自动路径均验证目标 SHA 检查结果。
  记录代码、配置、数据库 schema 兼容关系；受控紧急通道不能静默绕过正常门禁。
- 验收：坏配置/坏依赖初始化不能误报发布成功；回滚后业务探测通过；在途请求结束；
  数据库不兼容时阻止自动代码回退并进入恢复流程。
- 首期支持明确的单机维护发布，不在没有多实例演练的情况下承诺零停机。

### D14：数据与秘密治理

- 范围：TelemetryService、存储查询、Skill 凭据存储、Android 发布构建和运维文档。
- 增加音频/诊断分项配额、保留清理、分页、磁盘水位与丢弃指标；动作/安全审计独立可靠存储。
- 工具凭据改为秘密引用或受控加密存储，并定义密钥本身的保管与轮换；导出、日志和诊断禁止泄密。
- 检查 release 包中不应下发的秘密；本地厂商 SDK 凭据按其授权机制处理，不能承诺客户端秘密绝不提取。
- 验收：满盘/队列满可控；删除和备份恢复可验证；必要审计无法持久化时明确拒绝相关写动作。
- 待确认：原始音频是否采集、保留期、访问角色和备份保留范围。未确认前建议生产默认不持久化原始音频。

### D15：业务恢复协议

- 首期明确单实例重启恢复：客户端识别恢复失败并同步失效状态；导航列表能可靠恢复或要求重搜，
  不允许界面继续显示一个服务端已无法识别的有效列表。
- 动作账本与短期对话状态分别处理；不重播旧音频、不重放未经确认的写动作。
- 若 SLO 要求换实例继续会话，另开共享状态/ownership/fencing 工作包，不直接向所有模块插入 Redis 调用。
- 验收：断网重连、进程重启、候选过期、动作结果未知均有端到端结果；恢复时间和损失范围实测记录。

### D16：整体验收

- 增加不访问真实付费服务的 Classic/Omni 应用装配测试；保留现有 schema、单测、lint、覆盖率门禁。
- 自动故障场景覆盖 D02–D15；性能场景区分 fake 上游容量和真实供应商端到端能力。
- 真机覆盖：导航二轮序号/地址名、后台返回唤醒、播报打断、VAD 误报、多语种、蓝牙音频焦点、
  持续闲聊与退出、网络切换。手机或供应商凭据不可用时标记未验收，不能用 Stub 结果替代。
- 长稳时长、连接数、说话比例和付费测试上限在执行前确认；记录 p95/p99、错误率、队列、
  资源趋势、恢复耗时和费用，达到批准目标后才关闭风险。

## 4. 兼容、回退与完成定义

每个 PR 必须包含：

1. 风险编号、变更边界、前后行为及明确的不变项。
2. 单元/契约/集成测试，以及适用的故障注入结果；行为修复优先先写失败用例。
3. 协议和配置变化的兼容矩阵：旧客户端/新服务端、新客户端/旧服务端如何处理。
4. 新增指标和错误码；涉及数据库/凭据时附迁移、回退和数据保留说明。
5. 更新本计划状态及对应文档，附实际 PR、提交和验证证据。

工作流：从最新已合并基线创建 `codex/` 分支 → 本地验证 → PR → 必需 CI 与评审通过 →
获得合并指令后合并。部署独立验收。不能因“修安全问题”跳过兼容检查，也不能因兼容旧版长期保留
生产鉴权旁路。功能开关用于隔离未完成能力，不用于重新开启已禁止的越权路径。

状态使用“待开始 / 开发中 / 待 CI / 待环境验收 / 已完成”；合并不自动等于风险关闭。
生产配置与数据库迁移失败时，不以回退到无鉴权或无动作授权作为恢复方式。
