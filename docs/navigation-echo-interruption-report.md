# 播报回声进入打断识别：修复与真机对照

2026-11-13 用户在 Open 通道发现打断识别包含系统播报。近期设备轮次的 ASR 与前轮 TTS 相似度达到约 0.91–0.97，确认了自播报被当成输入的现象。原始用户语音文字与地点未写入本报告。

## 修复范围

1. 播放参考原先乘以 Android 报告的物理音量增益，本机实测约为 0.1148。改为向 WebRTC 送入与 AudioTrack 实际写入一致的数字 PCM，由回声算法估计扬声器到麦克风的衰减；仍监测静音、增益变化和路由变化并撤销失效参考。
2. 原先 100ms 参考包一到起始时间便全部推进 APM，参考时间甚至领先当前 100ms。现在按 10ms 片段的呈现时间消费，不重复消费或用未来时间证明参考可用。
3. 打断预卷不再任意回溯 384ms，而限制在连续有效参考区间内的声学起点前最多 20ms。声学 VAD 起点不是可靠的近端人声判定。
4. 音频批次生产前后参考均需有效。播放中候选捕获遇到失效批，在上传前取消该候选并保留导航任务；旧播放终止后解除该限制，避免后续回复误伤用户尾音。

## 同设备对照

测试播放已有公开 WAV，重复 13 次，共约 13.8 秒；用户被提示保持安静，但环境并非实验室控制。未保存麦克风 PCM，也未上传到云端。最后一轮仅在手机内存中交给 FireRed 检查，并只记录识别字符数量。
