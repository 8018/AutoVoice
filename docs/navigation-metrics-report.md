# 导航质量统计（I06）

应用通过现有遥测的 `POST /api/telemetry/events` 提交 `navigation_operation` 终态事件。每次操作使用独立随机 ID，语音和界面入口走同一统计路径。事件正文只包含固定枚举 `operation`、`result` 与单调时钟测得的 `durationMs`。该事件不携带地点名、地址、坐标、路线内容、语音文本、供应方错误文本或密钥。

## 操作和统计口径

| 操作 | 终态含义 |
| --- | --- |
| `plan` | SDK 或在线预览返回可用路线时计成功。覆盖重新规划和切换路线偏好。返回空路线、缺定位、能力不可用、失败、超时和取消分别记录。 |
| `start` | 收到与原请求匹配的 SDK 启动确认时计成功。拒绝、缺少精确定位权限和等待超时分别记录。 |
| `stop` | SDK 调用返回受理时计 `accepted`。SDK 当前缺少可靠的停止确认，受理耗时只涵盖本地提交。 |
| `search`、`cancel_search` | 沿途搜索收到有效结果时计成功，空结果、失败、超时及被取消分别记录。取消成功表示应用放弃原搜索并丢弃晚到结果。 |
| `map_visibility`、`map_control` | 地图显隐记录本地状态变更。缩放、概览、路况与卫星图记录 SDK 调用受理或失败。 |
| `audio_mute`、`audio_volume` | SDK 音频控制成功返回时计成功。无能力、控制失败与输入被拒绝分别记录。 |

`succeeded` 是操作定义范围内的成功。按操作统计时，用该操作收到的终态事件数作分母，并分别报告 `accepted`、`unknown`、`unsupported`、`missing_location`、`failed`、`timeout`、`cancelled`、`no_results` 和 `rejected`。等待结果期间不提交终态。过期或重复回调只关联原操作，终态在客户端只发出一次。界面导航状态继续按 SDK 的实际反馈更新，包括启动超时后晚到的有效确认。

## 数据与验收边界

- 既有 `execute` 遥测仍覆盖上游业务执行和外部高德 URI 交接。统计新事件时按 `navigation_operation` 过滤，避免把上游受理、外部交接和导航操作终态重复纳入分母。
- 现有服务端会保存独立操作事件及对应记录，可通过管理员明细接口 `GET /api/telemetry/rounds/{utteranceId}` 查询。独立记录缺少设备和会话归属。现有面板未新增导航成功率或延迟分位数，现有语音聚合也未按该阶段生成指标。
- 遥测未配置、上传未送达及进程异常终止会减少可用样本。当前证据来自自动测试和服务端代码核对，尚无实车终态样本、实车成功率或实车延迟分位数。
