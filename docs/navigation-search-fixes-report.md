# 导航找点故障修复

## 根因与改动

| 场景 | 定位依据 | 修复 |
| --- | --- | --- |
| 上海虹桥机场 T2 | 高德文本结果有 POI 编号、名称和地址，缺坐标。编号 B00156YASY 的详情返回“上海虹桥国际机场2号航站楼”和坐标 `121.328711,31.194180`。原逻辑只为带条件的请求查详情。 | 精确航站楼查同编号详情，重新核对航站楼和城市。识别 `T2`、`T2航站楼` 和 `2号航站楼`，排除机场本体、出发区及停车场等不同地点。 |
| 三亚凤凰国际机场 | “请说要查找的城市”来自缺定位、城市和参考点的搜索前置检查。目的地含“三亚”但原有前缀规则不识别这种写法。高德 POI B03830MO6S 的名称与完整输入一致，详情城市为三亚市。 | 提示模型提取连写在地点前的城市。只给出完整机场名称时允许精确名称查询，校验同编号坐标并排除同机场的子设施和其他机场。缺定位和城市的泛类查询继续澄清。 |
| 北京星巴克 | 文本结果返回名称、地址和编号，缺品牌条件结果需要的坐标。dev 技能清单此前没有启用已经存在的 `maps_search_detail`。详情能提供北京的分店名称、分类和坐标。 | dev 通过技能管理接口启用该只读工具。配置变更后的真实请求已返回三个星巴克候选。增加一项同响应形状的品牌证据回归。[配置变更后复测](qa/navigation-benchmark-runs/2026-11-13T06-32-00.889Z-9a316f6.json) |
| 北京南站附近的充电站 | 搜索“南站”或“北京南站”时，高德会返回“北京南站”和相关地铁站、公交站及附属设施，文本结果缺坐标。旧逻辑无法匹配含城市前缀的正式名称，或只能尝试地理编码。编号 B000A83AJN 的详情确认站点坐标 `116.378517,39.865246`。周边充电站结果也只带编号、名称、地址。 | 用明确城市匹配简称和完整正式名称，检查是否只有一个精确参考点，按同编号详情取坐标。周边站点也按同编号取坐标并检查五公里半径。候选继续提示充电桩空闲状态未知。 |

地点详情沿用 400 毫秒节流与限额退避。每次目的地搜索最多请求五个详情，凑齐可展示的候选即停止。参考点仅在命中唯一地点时补一次详情。没有详情工具时仍由现有地理编码验证提供可用候选，否则返回澄清或未核验。营业状态、充电状态和补能规划仍取决于可核验数据。

## 验证

- 四个响应形状回归先跑旧代码，航站楼、机场和充电站三项失败。品牌条件在详情已启用的模拟响应中通过，与配置层诊断一致。另对 `T2航站楼` 字段和重复参考点参数做失败再通过验证。
- 使用 Java 21 执行 `./gradlew --offline :skill-mcp:test :navigation-domain:test`。地图技能 96 项，导航域 41 项，失败和错误均为零。
- dev 网关日志未记录这四次历史请求的原始模型参数。直接使用 DeepSeek 重现参数的独立探针因需向外部发送内部系统提示词和工具定义被自动审批拒绝，未执行。测试采用工具参数形态和从实际高德调用获得的响应字段。配置层复测已完成，代码部署及端到端复测由主任务执行。
