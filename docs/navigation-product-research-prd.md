# AutoVoice 车载语音导航调研与产品需求

版本：评审草案 v1.0　调研日期：2026 年 11 月 12 日

配套文档：[58 项导航产品清单](navigation-product-checklist.md)；[按分类实施计划](superpowers/plans/2026-11-12-navigation.md)。

## 1 产品结论

导航应从少量地点指令，发展为覆盖「表达需求—确定地点—规划路线—启动—途中调整—结束」的连续任务。优先完成准确找点、多轮纠错和可靠交接；接入地图控制与实时状态后，再开放选路、结束导航、剩余时间和沿途搜索。复杂出行规划与补能最后推进。

本文面向 AutoVoice 的产品、开发和测试。竞品部分属于公开资料调研，未进行实车测试；后文需求及话术均为本项目建议，不代表竞品原话或当前已实现功能。范围以中国市场为主，能力仅归属于所引资料对应车型和版本，不推广为品牌全系能力。

## 2 真实竞品能力与证据

证据等级：A 为品牌官网或官方手册；B 为媒体转述发布内容、第三方托管的车型手册；C 为社区经验，仅用于后续验证。没有找到直接证据的能力记为待核验，不等于不支持。

### 2.1 特斯拉

**已确认，A：** 中国官网指令表明确列出目的地导航、结束导航、导航静音与恢复、地图缩放、交通图和卫星图切换、清除导航搜索。官方示例包括“去陆家嘴”“导航取消静音”“显示路况”。说明其语音导航包含地图展示控制，而不只是发起导航。[特斯拉语音指令表](https://www.tesla.cn/support/voice-commands)

**已确认，A：** Model Y 手册支持导航回家、去公司和查找附近超级充电站；家和公司需预先定义。多途经点等地图功能是否能全程通过语音操作，不能仅凭地图功能存在推定。[Model Y 车主手册](https://www.tesla.cn/ownersmanual/modely/zh_cn/Owners_Manual.pdf)

产品启发：把搜索、行程控制、地图展示、播报控制分别建模；“导航静音”不能误操作媒体音量，“清除搜索”不能等同结束行程。

### 2.2 小米汽车

**有发布依据，B：** 2026 年 3 月 31 日 IT之家转述小米智能助手官方发布，适用对象为新一代 SU7：模糊特征搜索、联网推荐、沿途找点并添加途经点、多地点串联规划，以及结合上下文调整行程。该资料证明发布范围，不构成各配置实车识别率或所有老车型覆盖率证据。[新一代 SU7 超级小爱升级内容](https://www.ithome.com/0/934/548.htm)

产品启发：用户的输入可以是需求和约束，而不是完整地名；系统需要保存行程草稿，允许补充与修改。下列为本项目拟用话术，不是发布原话：“先接人，再去机场”“找沿途的咖啡店”“刚才那个地方不去了”。

小爱开放平台具有地图协议条目，但平台提供接口不等于某辆小米汽车已经交付相同能力，因此不将平台接口表作为车型支持证明。

### 2.3 理想汽车

**有手册依据，B：** 第三方托管的理想 L7 手册展示多人导航流程：提出目的地、选择地点序号、选择路线序号、确认开始。它证明手册描述过完整多轮流程，但托管来源与较早车型限制了对现款的推广。[理想 L7 手册镜像](https://chats.chinamobil.ru/files/lixiang-li-l7-l8-l9/applicationpdf/Lixiang%20L7%20Owner%27s%20Manual.pdf)

**有报道依据，B：** 2026 年 11 月 9 日中国质量新闻网报道 OTA 9.2 的地图出行 Agent 支持多地点、指定行经道路、长途充电和休息安排及多轮调整；报道限定新一批车型，并要求登录高德账号、开启理想同学专家模式。本文不把它认定为所有理想车辆已可用。[OTA 9.2 报道](https://www.cqn.com.cn/auto/content/2026-11/09/content_9180040.htm)

**边界，A：** 官方 VLA 泊车资料中的驶出地库、前往停车区域属于辅助驾驶执行，与普通导航路线规划不同，不纳入 AutoVoice 本轮导航需求。[理想 VLA 泊车说明](https://manuals.lixiang.com/zh-cn/W1012026HOME/20260902090112/7a113be8c736.html)

产品启发：地点候选和路线候选必须使用不同上下文；多人参与时需要明确谁能确认或改动行程。

### 2.4 比亚迪

**已确认，A：** 宋 Ultra EV 官方用户手册正文第 308 页列出语音启动导航，明确示例为“导航到市民中心”，支持方向盘按键或“你好小迪”唤醒。本次可核对的官方证据支持基础目的地语音导航，尚不足以确认该车型完整的语音途经点、偏好、沿途搜索和 ETA 查询清单。[宋 Ultra EV 用户手册](https://www.byd.com/material/domestic-official/user-manual/dynasty/宋Ultra%20EV%20用户手册20260402.pdf)

**辅助证据，B：** 第三方托管的秦 L 手册描述语音导航、连续对话和打断，但不能由“支持连续对话”推定所有导航操作均可多轮修改。[秦 L 用户手册镜像](https://www.scribd.com/document/838634260/秦L用户手册)

**排除的证据，C：** 社区适配版高德列有沿途搜索、选路、途经点和偏好等指令，但涉及第三方安装及版本适配，不能作为原厂全系能力。[迪粉之家适配版说明](https://www.difans.cn/post_byd_car/314.html)

产品启发：能力声明应跟随车型、地图应用和版本；系统必须知道当前执行端究竟支持哪些操作。

## 3 AutoVoice 当前基础与缺口

依据仓库导航说明及 NavigationExecutor、NavigationSession 的静态阅读，当前已有：地点候选展示、后续选择、任务身份与候选版本校验、单终点和有序途经点交接、外部地图打开结果记录、取消本地候选。

关键限制：高德 URI 打开成功只能证明交接被接受，不能证明导航已开始；多地点交接进入路线规划页，也不等于已经开始行驶引导。当前不能据此判断到达、偏航、真实剩余时间或成功结束外部地图导航。SOC 仅预留，不具备可靠补能数据链路。本次未运行应用或重新执行测试，不将静态能力当作真机验收结果。

项目依据：[导航状态说明](../docs/navigation-domain-state.md)、[导航执行器](../AutoVoice/voice-business/src/main/kotlin/com/autovoice/voicebusiness/navigation/NavigationExecutor.kt)、[导航会话](../AutoVoice/voice-business/src/main/kotlin/com/autovoice/voicebusiness/navigation/NavigationSession.kt)。

## 4 目标与实施取舍

目标：用户无需背固定句式，可以准确表达目的地、补充限定、纠正选择；每次回复与执行结果一致；高频导航任务尽量不需要触屏。

不包含：语音操纵车辆转向、变道或泊车；绕过地图应用权限；没有实时数据的电量、到达时间或路况推测。

可选方向：仅增加同义句投入较小，但行中任务仍无法完成；直接建设完整出行助手覆盖广，但高度依赖地图和车辆数据；建议采用分阶段方案，先完善找点与交接，再建设可验证的行程控制，最后扩展复杂规划。此为产品建议，尚未形成开发排期或批准的实现方案。

## 5 功能需求与优先级

下表话术均为 AutoVoice 设计样例。P0 为当前形态优先补齐，P1 以地图接口与回调为前提，P2 以完整行程和车辆数据为前提。表中已具备基础的能力仍需统一体验与验收。

| 编号 | 用户任务及话术样例 | 预期行为 | 优先级与条件 |
|---|---|---|---|
| N01 | “带我去虹桥机场”“上海虹桥 T2” | 提取城市、地点、航站楼，检索具体入口；不以机场中心点代替已要求的航站楼 | P0 |
| N02 | “找附近的停车场”“人民广场附近的咖啡店” | 区分当前位置周边和指定地点周边；展示候选与地址 | P0，定位或参考地点可用 |
| N03 | “第二个”“浦东那个”“不是这个，换一批” | 在当前候选内选择、限定或重搜；无匹配则澄清 | P0 |
| N04 | “不去机场了，去火车站” | 替换待规划目的地，使旧请求结果失效 | P0；已交接行程修改属 P1 |
| N05 | “先去学校，再去超市，最后回家” | 按表达顺序组成行程草稿；缺失地址逐项补齐后交接 | P0；家地址需存储支持 |
| N06 | “算了”“取消这次搜索” | 取消当前候选任务并保留已交接行程记录 | P0 |
| N07 | “回家”“去公司”“把这里设为公司” | 未设置时引导添加；覆盖已存地址前确认；按用户隔离 | P0 新增地址管理 |
| N08 | “不走高速”“少收费”“走第二条路线” | 以真实地图路线比较时间、距离、收费；偏好无解时说明 | P1 路线规划与选择接口 |
| N09 | “顺路找个厕所”“沿途找充电站” | 沿当前路线搜索，按额外绕行成本排序；保留原终点 | P1 当前路线与沿途检索 |
| N10 | “加一个途经点”“不去超市了”“先去医院” | 添加、删除、重排行程；变更后重新规划，成功后提交新版本 | P1 行中更新接口 |
| N11 | “还有多久”“几点到”“还剩多远” | 查询当前有效路线的实时数据，并区分预计时间与保证到达 | P1 实时状态 |
| N12 | “结束导航”“继续刚才的导航” | 明确目标行程；仅在执行端确认后播报完成 | P1 控制及恢复能力 |
| N13 | “导航别说话”“恢复导航语音”“导航声音小一点” | 只调整导航通道；反馈实际结果 | P1 播报控制 |
| N14 | “放大地图”“看看全程”“显示路况” | 调整地图视图，不变更行程 | P1 地图展示控制 |
| N15 | “找一家现在营业、适合带孩子吃饭的店” | 将需求转成可核验条件；缺少营业或设施数据时说明 | P2 数据来源及新鲜度 |
| N16 | “规划途中充电，到目的地至少留两成电” | 依据 SOC、车型能耗、兼容充电站和路线规划；展示假设与方案 | P2 车辆及充电数据 |

## 6 关键对话与状态规则

### 找点与纠错

用户：“去虹桥。” 系统：“去虹桥机场还是虹桥火车站？” 用户：“机场，T2。” 系统显示明确候选；用户确认后才交接。若城市不明确且附近存在不同同名地点，优先澄清城市或地址。

建议同屏最多 3 个候选，按当前顺序编号，显示名称、区域和地址。距离必须标明口径：直线距离不冒充驾车里程。候选变化时重新编号；过期的“第二个”不得作用于新列表。

### 多地点与行中修改

用户：“先去学校，再去机场。” 系统分别解决两个地点，简短复述顺序；不可擅自按距离重排。用户只说“取消学校”时仅删除该途经点；删除终点需补充新的终点或确认结束。

行中用户：“找沿途的咖啡店。” 系统产生候选，原路线继续；用户放弃搜索时原路线不变。确认新增后，只有地图更新成功才回复“已加入途经点”。新增失败保留原路线。

### 查询、取消与反馈

“去机场多久”是查询，不自动开始导航。“不要取消导航”是否定，不应触发取消。“取消”优先作用于正在进行的选择任务；没有待选任务且无法控制外部地图时，回复“我暂时无法结束高德里的导航，请在高德中操作”。

当前交接成功建议回复“已为你打开高德，请确认路线”，不得回复“已到达”或保证“已开始导航”。打开失败应明确告知未完成，并提供重试入口。执行失败不能被语言模型的成功话术覆盖。

### 状态与数据约束

将搜索任务与实际行程分离。搜索包括检索中、待选、已确认、取消、过期；当前行程只保留未交接、交接中、已接受、失败。接入真实回调后，才增加导航中、到达、已结束。

每次选择绑定任务、列表和候选身份；每次路线变更绑定行程版本。过期结果不得覆盖新任务；同一确认不得重复打开地图。启动新搜索不自动结束现有行程。

执行端应提供能力清单，区分搜索、路线规划、实时查询、行程修改和地图控制。超出能力时明确降级，不能通过生成自然语言假装执行。

默认只接受被唤醒后的明确导航请求。多人同时发出冲突命令时不同时执行；P0 不以未经验证的声源定位推断驾驶员身份，先澄清。家庭地址和历史记录按账户隔离，产品提供删除入口，普通日志不直接记录完整家庭地址。

## 7 异常处理

| 情况 | 产品行为 |
|---|---|
| 定位权限关闭或位置过旧 | 提示开启定位或提供参考城市；不承诺“最近” |
| 网络或地图检索失败 | 保留有效行程；告知本次查询失败，可重试 |
| 无结果或同名结果过多 | 请求一个关键限定，不编造候选 |
| 家、公司未设置 | 引导设置；不猜测私人地址 |
| 高德未安装、无法打开 | 明确交接失败，提供重新打开或安装提示 |
| 当前路线未知 | 不回答实时剩余里程，不将历史终点当作当前导航 |
| 地点营业、停车余位或充电桩数据缺失 | 将属性标记为未知，不做可用保证 |
| 路线偏好无法满足 | 告知无法满足的条件并提供替代路线，由用户选择 |
| 用户打断或取消后旧结果返回 | 丢弃旧结果，不再执行或播报成功 |

## 8 验收与衡量

以下为拟定上线门槛，非当前测量结果。先建立不少于 200 条表达的基线集，覆盖标准说法、口语、别名、否定、纠错、同名地点、多地点和异常；分别在安静与道路噪声环境真机测试，按场景单独报告，不能只给整体平均值。

核心指标：明确单地点任务成功率建议不低于 95%；两轮选点成功率建议不低于 90%；取消后误执行、旧候选误选择、未执行却播报成功在验收集中必须为 0。失败请求计入分母，只有事先定义的超出范围场景单独统计。网络正常条件下，用户说完到首条有效反馈 P95 建议不超过 2 秒，到候选结果 P95 建议不超过 5 秒；超时先反馈进度，不编造结果。

| 验收场景 | 必须观察到的结果 |
|---|---|
| 明确终点 | 地点与坐标匹配，最多执行一次交接 |
| 同名机场及航站楼 | 选择具体航站楼；不直接选错城市或机场中心 |
| “第二个” | 精确选择当前列表第二项；过期列表不执行 |
| “不要去第二个” | 不触发对第二项的肯定选择 |
| A→B→C | 终点为 C，途经点顺序 A、B 不变 |
| 候选出现后取消 | 关闭选择；不启动地图 |
| 取消后收到迟到结果 | 不恢复候选、不执行导航 |
| 地图打开失败 | 保持失败状态；播报未完成 |
| 地图仅接受打开 | 只报告交接，不报告导航中或已到达 |
| 查询“多久到”但无实时数据 | 明确无法获取；不生成数字 |
| 行中增加途经点失败 | 原路线保持不变，不播报添加成功 |
| 导航静音 | 媒体音量不变，地图返回成功后才确认 |

真机记录至少包含车型或设备、系统及地图版本、网络、原始表达、识别结果、候选、用户选择、执行回执和最终显示。竞品复测也使用同一套记录；只有官方资料并不足以比较识别准确率。

## 9 分期交付与待决事项

第一期：完善 N01—N07，建立口语语料和失败提示，修正交接成功话术，验收多轮候选与有序途经点。家和公司需要新增存储及设置入口，不能仅加同义词。

第二期：确认地图 SDK 或车机控制协议可用，完成状态回调后开放 N08—N14。退出导航、行中修改和实时查询必须通过端到端真机验收，接口未就绪时保持明确不可用。

第三期：开放 N15—N16，逐步引入实时营业、补能和偏好信息；先保证可核验的条件规划，再做主动建议。

评审需确定：首发是手机伴随应用还是原生车机；地图供应方可提供的控制与回调能力；地址数据保存方式；首期覆盖城市、口音及网络条件。以上影响开发范围与工期，本文不预设具体排期。
