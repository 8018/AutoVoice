## 1. 结论

保留模块化端云架构、两级仲裁、会话状态机、导航领域和统一播放边界。
将普通导航/模拟车控从“持久化动作签发及跨重启防重”收敛为“当前交互内一次执行”。

不能只删除数据库：当前确实存在音频请求重试和服务端结果重放，必须先收敛这些路径，再解除账本依赖。
身份、凭据、权限、资源生命周期、背压、就绪探测等生产化工作不因移除账本而撤销。
本次不等同于对 D01–D16 全部代码和实机行为的验收通过。

## 2. 新的产品契约

1. 一次话语服务当次交互；连接故障结束受影响的云端请求，不重传这轮音频，不补执行其结果。
2. 恢复连接用于未来的新话语，不恢复旧的待执行任务；进程重启不恢复旧轮。
3. 用户重新说相同指令是新请求，不能用文本或参数相同将其误判为重复。
4. 网络错误不是“拒识”：界面/指标区分连接失败、语义未命中、执行拒绝和执行结果未知。
5. 云端断线不自动否定已经获准的本地动作；本地候选的优先级继续由既定仲裁规则决定。
   若交互已经在会话层结束，后来才到的本地或云端结果都不能触发动作。
6. 已交给外部导航应用的动作不因断网被撤回；没有回执就不伪报未执行或成功，也不自动再发。
7. 不增加 VAD 建轮/停播逻辑。候选落败或轮次替代仅拦截输出，不通过取消计算实现防旧结果。

“断线失败”不代表以后不能重连，也不代表任何一次无关后台连接波动都必须打断已在本地完成的业务。
新的连接代次与业务轮次是不同概念：前者过滤过期传输事件，后者由会话状态机管理。

其中 `...` 对应该模块的 `src/main/kotlin/com/autovoice/app/`。
服务端文件在 `AutoVoiceServer/gateway/src/main/java/com/autovoice/server/gateway/`；
账本在 `AutoVoiceServer/action-ledger/src/main/java/com/autovoice/server/actionledger/`；

## 4. 目标架构与保留边界

| 模块/职责 | 目标 |
| --- | --- |
| GatewayClient/连接管理 | 可重新建连，但不能拥有旧话语重传队列；旧连接事件不进入新连接交互 |
| ASR/模型候选 | 并发输入、独立识别事件；按自身期限收尾，不因落败而取消 |
| 两级仲裁 | 按该轮业务优先级选语义、同轮只输出一次；不知道当前轮 |
| ConversationController/输出协调 | 唯一当前轮和结束状态；统一判断晚到结果能否用于界面、动作和播放 |
| 导航领域 | 继续保留 prepare/adopt、selectionId、candidateId 和 TTL；这些解决列表一致性，不是交易账本 |
| 轻量执行门 | 原子地校验本轮仍有效并领取一次执行权；不落盘、不在重启后恢复 |
| 业务执行器 | 参数/状态检查，导航/模拟动作白名单，返回执行或交接结果；真实车控继续关闭 |
| 日志/审计 | 记录事实供排查，不反向决定普通导航能否执行，不负责恢复旧动作 |

**不要删除 `SemanticEmissionLedger`。**它是 voice-core 的有界内存逐轮语义输出记录，不是本次要去掉的
持久化动作账本。名称包含 Ledger 不能作为删除依据。`TurnOutputPermit`、RequestKey、任务关闭登记也保留。

### 4.1 轻量执行门的具体语义

- 准入检查与领取执行权在同一串行会话调度边界完成，或采用等价的原子机制；不能先检查、隔很久再执行。
- 普通语义动作使用稳定的当前轮执行槽位，不在每次回调中随机生成新去重身份。
  若一份已采用结果明确包含多个动作，使用既有动作序号区分；不借此引入新的多动作产品能力。
- 输出音频块不消耗动作槽位；导航 choose 与用户下一轮 select 是不同交互。
- 一次领取后成功、失败或未知均不重新开放该槽位；用户重说才建立新轮。
- 会话结束禁止新领取；已交接到外部应用的动作按实际结果收尾，不能承诺可撤回。
- Realtime 不得使用空 turnId 绕过检查。若首期仅闲聊，则不执行其业务意图；保留显式进入/退出闲聊控制。
- 失败只反馈一次。结果类型至少区分：已交接/已应用、拒绝、未开始即失败、结果未知、重复/旧轮丢弃。

### 4.2 重连与导航的区分

连接可以预先恢复，为下一次话语准备；恢复期间不积攒已经失败话语的音频等待补发。
正常恢复同一逻辑会话且候选仍有效，可保留已采用的列表供用户新话语选择；
服务端明确重置会话、候选丢失或过期时清列表。列表恢复不是恢复旧的待执行导航动作。
没有采用确认的候选，不在重连后自动采用。旧 ACK/错误/流完成回调必须受连接代次及业务版本保护。
SharedFlow 的 replay 配置不能机械删除：先区分连接状态补发与业务结果重放，再调整订阅和过滤。

## 5. 审计如何收敛

普通导航/模拟车控记录：轮次标识、来源、动作类型、准入或拒绝原因、交接/执行结果和耗时。
不默认记录原始音频、完整地址、秘密值；必要信息按现有数据治理规则控制。
普通诊断故障不阻断这两类交互，但必须有丢弃计数；不能把诊断日志当作执行恢复依据。

设备凭据吊销、管理登录及配置修改等安全事件保留独立审计策略。
未来有真实敏感写动作，再单独评审授权、可靠审计和下游结果核实；本次不开放它们。
审计页面仍可复用数据平台，不新增平台。现有 action_audit 是计划签发审计，不得改名冒充动作执行审计。

## 6. 协议与数据退出策略

1. 过渡期保留可选 actionId/actionExpiresAtMs 的解码兼容；新客户端不再将其作为本轮准入或跨重启执行依据。
2. 增加明确能力协商或最低客户端版本门禁。旧客户端依赖非空 actionId，不能先让新服务端停止签发后静默拒绝动作。
   推荐先支持并发布新客户端，确认设备升级后启用新服务端语义；旧版在新模式下明确拒绝连接/动作并提示升级。
3. 兼容阶段如仍需旧字段，可保留不落盘的关联 ID，不能因此继续开启旧请求重放。字段最终删除另行版本升级。
4. 删除 AppConfig/Gradle 的动作账本运行依赖和对应环境必填项之前，核查健康探测、备份、清理脚本和测试引用。
5. 停止读取/写入历史账本，不自动删除服务器或手机数据库文件。现有审计数据保留策略继续有效；
   实际归档/删除独立批准。禁止为了清理无用库而误删其他 SQLite 数据。
6. 不把回退到旧版“自动补发”作为透明回滚；发布说明必须列出客户端/服务端支持组合和行为差异。

## 8. 必须更新的验收矩阵

| 场景 | 新的通过标准 |
| --- | --- |
| 上传前/中/等待结果时断网 | 本次云端请求明确失败，无第二次 audio_start 和旧 PCM 补发 |
| 连接自动恢复 | 只使未来新话语可用；不能触发旧回复、旧采用确认或旧动作 |
| 旧 socket 回调晚到/订阅重建 | 旧结果不更新新轮，不播放，不执行 |
| 同轮本地或流式动作回调重复 | 一次领取，一次执行；后续音频块仍可正常播放 |
| 进程重启 | 不读取动作库恢复任务；用户重新说相同内容可正常执行 |
| 已调用外部导航后丢回执 | 不重发；不误报未执行或已完成导航 |
| 账本文件缺失/不可写 | 新版普通导航与模拟车控不受影响；其他必要配置失败仍按安全策略处理 |
| 诊断队列满 | 普通动作不依赖诊断持久化；丢弃可观测，敏感管理审计策略独立 |
| 本地优先结果与云端断网并发 | 不改变优先级；已经结束的轮不接受迟到动作 |
| 导航列表正常恢复/服务端重置 | 前者仅供新一轮选择，后者清列表；不补执行历史选择 |
| 新旧客户端/服务端混用 | 约定组合正常，其余明确要求升级，无静默拒绝或恢复旧重试 |
