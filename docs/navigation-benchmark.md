# 导航量化回归基准

每批导航改动必须按“修复/实现 → 离线测试 → 部署 dev → 完整文本、路线、合成语音和统计基准 → 修复失败项 → 再跑完整基准”执行，完整通过后才能开始下一批。自动检查不能替代人工确认新功能语义，也不能替代真机语音与导航验收。

## 固定文本套件 v3（保留 v1、v2）

初始 v1 为 16 个场景、23 次文本请求：找点、城市、航站楼、带中文数字地名、品牌、营业限制、周边充电站、补能数据缺失、有序多站、常用地址能力、实时耗时边界、只读路线、否定选择、城市纠正、换批和取消。旧版原始结果保存在 `docs/qa/navigation-cloud-text-results.json`，不得覆盖。新场景追加并升级套件版本，不通过删除失败项、放宽规则或改变原句使其变绿。

判定同时检查回复类型、结构化动作、候选坐标和名称、城市范围、任务/候选身份、草稿顺序和重复地点。四个无法在纯云端完成的项目（营业核验、真实补能、端侧常用地址、活动导航状态）单独标记能力边界反馈，不能计作这些产品功能完成。

v2 追加航站楼别称、城市市后缀、品牌加类别、完整参考点四条，当时为 20 个场景、27 次请求；旧 23 条集合和新增 4 条分别报告并验门槛。

当前 v3 完整门槛：全部 33 次有结果，语义失败/缺测/超时为零，平均完整回复 <= 2500ms，P95 <= 5000ms。性能阈值是本轮采用的工程默认值，不是用户指定的生产 SLO。耗时从客户端发送到最终回复，包含网络、模型及搜索，不含握手、语音与设备执行。P95 用 nearest-rank。新功能变慢时必须解释和改善，不能静默调整阈值。

## 运行

```sh
node --test tools/qa/tests/*.test.mjs
node tools/qa/navigation-cloud-text.mjs --release=实际部署版本
node tools/qa/navigation-route-benchmark.mjs --release=实际部署版本
node tools/qa/navigation-voice-benchmark.mjs --release=实际部署版本
# 在门槛之外增加稳定性样本：
node tools/qa/navigation-cloud-text.mjs --release=实际部署版本 --repetitions=3
# 仅用于诊断，不能替代完整套件：
node tools/qa/navigation-cloud-text.mjs --release=实际部署版本 --focus=entrance,numeric_city,brand,charging
```

本机读取忽略入库的 `AutoVoice/local.properties` 中 `gateway.authToken`；也可通过 `NAVIGATION_BENCHMARK_TOKEN_FILE` 指向权限受限的文件，或使用环境变量 `NAVIGATION_BENCHMARK_TOKEN`。默认 dev；CI 通过 SSH 隧道使用 `NAVIGATION_BENCHMARK_ENDPOINT` 指向 dev。不会将令牌写入结果。

每次生成独立的 `docs/qa/navigation-benchmark-runs/<UTC时间>-<代码版本>.json`，包含套件版本、源码版本、声明的部署版本、每条输入/回复/动作、断言失败原因、完整耗时及与原始基线的逐条变化。退出码非零表示未过门槛。非完整套件始终有 `fullSuite:false`。

CI 每次改动跑判定器契约测试；dev 部署流程在激活后通过 SSH 读取私有设备令牌并连接本机网关，执行完整套件，保存结果为构建附件。失败使部署检查失败，不能声称新版本验收通过；它不会自动恢复旧版服务。手动部署同样执行完整命令。GitHub 工作流要在本分支合入后才会在远端生效。

## 供应方配置

地图候选须用真实坐标。dev 高德 MCP 启用 `maps_text_search`、`maps_around_search`、`maps_geo` 和 `maps_search_detail`；详情按相同 POI ID 补充位置和分类，不能把地理编码中心当作指定航站楼。配置修改也视为导航变更，必须跑基准。原来的品牌搜索缺详情能力是本次已验证的部署配置问题。

## 随业务扩充（用户追加要求）

每批新功能必须同步增加可重复用例，并关联 58 项清单中的产品 ID。优先覆盖正常成功、缺参数/能力、供应方失败/超时、否定/取消、状态过期和多轮纠正；不适用的维度说明理由。旧用例永久保留，套件版本递增。

报告分别呈现旧版固定集合、新增集合及各产品项的目标达成率、边界反馈、失败原因和延迟，避免扩充分母后掩盖旧功能回归。端侧或管理统计功能增加对应离线/接口契约用例，不把无法通过云端文本触发的业务伪装成文本验收；仍需跑全部既有文本基准。

## 业务接口补充套件

文本 v3 套件为 33 条（原始 23 条 + v2 新增 4 条 + v3 新增 6 条），各版本分组单独检查正确率和耗时。I06 新增 3 项只读实测：无样本为空、非法或缺失时间窗拒绝、管理页面和实际资源可用；以及 5 组设备归属、去重、统计和界面离线契约测试。D02 新增 3 项路线接口实测：混合 WGS84/GCJ02、途经顺序和缺起点拒绝。路线单次门槛 10 秒，单独统计，不混入文本平均值。

运行 `node tools/qa/navigation-route-benchmark.mjs --release=实际版本` 验证官方路线转换。通过 SSH 在 dev 运行 `python3 - --dev-env < tools/qa/navigation-statistics-benchmark.py`（脚本从标准输入送入远端）验证统计接口；只读，不上传假样本。发布脚本已包含这两组，并保存对应结果。业务覆盖总表见 [分层业务基准](qa/navigation-business-benchmark.json)。

### v3 精确地点补充

在旧输入及规则保持不变的基础上，追加车站全候选身份、博物馆本馆/分馆、城市类别查询、机场简称和精确目标换批共 6 条请求。候选耗尽允许明确说明没有更多，但网络失败、重复候选或无关地点不能通过。新旧各版本分别设耗时门槛，避免扩充后的总平均掩盖退化。

## 合成语音补充套件 v1

文本 v3 的 33 条和原门槛保持不变。新增语音套件从 dev TTS 合成公共地点指令，验证实际音频经过云端 ASR 后的导航回复；不会上传私人录音、读取设备位置或执行地图动作。

| 用例 | 产品 ID | 检查内容 | 独立门槛 |
|---|---|---|---|
| voice-candidates | A03、B01 | 合成“找北京的博物馆”，按 16 kHz 单声道 PCM 每 20 ms 发送 640 字节；必须返回实际 ASR、2–3 个北京候选、对应编号和名称、有效坐标及候选身份 | audio_start 至最终回复 ≤15 秒，包含音频上传时长、云端 ASR、模型和搜索 |
| voice-select-second | B02 | 在同一连接采用候选后合成“第二个”；必须返回当前第二项完全一致的名称、坐标、候选 ID 和选择 ID，只检查动作，不执行 | 同上 ≤15 秒 |
| candidate-reply-tts | B01 | 请求合成上一轮完整编号候选文本；校验音频格式和非空内容，时长至少 1 秒 | TTS 请求至完整音频 ≤15 秒，单独报告，不混入文本或语音回复延时 |

准备指令音频的 TTS 耗时单列为 `fixtureTtsMs`，不计入语音回复门槛；候选回复音频时长也不等于 TTS 请求耗时。缺回复、ASR 不符、身份或坐标不符、超时及无效音频均使脚本非零退出。离线判定器覆盖通用提示漏报名称、缺第二项、重复身份、非法坐标、选择串线、缺失 ASR、延时越界、畸形/截断 WAV 和未声明格式的原始 PCM；模拟连接测试保留文本和路线接口兼容性。

这是**合成语音的云端链路检查，不是真机麦克风、实际扬声器听感或驾驶验收**。TTS 返回的 `text` 是请求回显；音频非空且时长有效，仍不能证明每个候选名字实际可听清。端侧显示、送入 TTS 的文本、实际播放内容和本地 ASR 仍需分别验收，不能用本套件通过替代。

每次结果写入 `docs/qa/navigation-voice-runs/<UTC时间>-<源码版本>.json`，记录独立套件版本、指纹、源码及部署版本、脏工作区标识、每项产品 ID、语义检查和分通道延时。部署脚本沿用同一 dev SSH 隧道与私有令牌执行，CI 无论成功失败都保留该目录结果；无需增加或打印凭证。

首轮公共合成语音[实测结果](qa/navigation-voice-runs/2026-11-13T14-17-32.704Z-926a679.json)为 3/3 通过：找点 3101 ms、第二项选择 682 ms、候选 TTS 1201 ms（音频 14442 ms）。源码为 926a679 的未提交工作区，部署版本 b8a9f27；不能据此声称该工作区已部署。首轮文件保持原样，其第二项产品 ID 误标为 B01，脚本后续结果已更正为 B02。
