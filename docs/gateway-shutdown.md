# 网关关闭资源清理

## 已观察到的问题

2026-09-08 发布 PR #33 时，旧网关在 SIGTERM 后 90 秒未退出，systemd 使用
SIGKILL 结束旧进程；新进程随后正常启动。这说明存在停止阻塞，但当时没有线程栈，
无法确定卡在哪个资源的关闭过程。不能把某一处代码缺陷直接等同于此次超时根因。

## 本次修复

连接断开和网关 bean 销毁共用资源清理入口：

- 撤销该连接的闲聊打开请求，避免尚未完成的打开操作继续按请求有效处理。
- 摘除并取消正在打开的流式识别。
- 上游取消抛出异常时，仍关闭闲聊资源和连接线程池，继续处理其他连接。
- 重复关闭不重复取消已经摘除的识别流。

只用于连接拆除和服务关闭，不改变日常轮次、VAD、ASR、新会话或仲裁规则。
没有缩短 systemd 超时，也没有增加生产强制重启操作。

## 验证与边界

网关回归覆盖两个并行连接的取消异常、清理继续执行和重复关闭。
这不是有界退出的完整保证：供应商 cancel/close 本身仍可能阻塞。
下一次计划发布如再次出现等待，应在强杀前采集 JVM 线程栈定位阻塞点；
不要为了复现主动中断用户正在使用的生产服务。
