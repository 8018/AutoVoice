## 本次实现

手机使用单调时钟判定定位年龄，接受 0–120 秒内且水平精度 0–500 米的定位。
无精度、未来时间、过旧或精度过差的位置不再上传。阈值为初始产品策略，可后续按实测调整。
应用回前台、开始录音或取得权限时尝试定位刷新；GPS/network 最多监听 8 秒，取得有效位置后立即退出。
退后台和 ViewModel 销毁均注销监听。刷新异步进行，不等待定位才传语音；本轮可能仍无有效位置。
界面提示权限不足、刷新中或建议说明城市。新鲜缓存仍然优先使用，不持续开启 GPS。

网关每次 audio_start 清除上轮位置，再采用本轮合法位置，并在 openStream 前准备上下文。
本轮缺少位置不会继续使用上一轮坐标；不修改设备系统定位、不填写模拟位置。

泛化机场搜索先召回至多 20 条，再合并同一机场、优选主体、过滤酒店/停车场/货运等附属 POI，
避免前几条全是同一机场的航站楼。最终仍最多展示 5 个候选。
排序顺序为国际机场主体、其他机场主体、航站楼等；同档按当前位置球面距离排序。
名称规则仅是启发式，不能断言机场是否民用、在运营或提供客运。
显式查询航站楼或停车场不适用泛机场去重过滤，保持用户要求的目的地粒度。
城市逆地理编码结果也用于后续 geocode，降低无坐标 POI 被解析到异地的风险。

## 2026-09-30：火车站与多地址导航修复

### 业务调研与处理策略

参考官方文档（2026-09-30 查阅）：

- [Android Assistant 导航意图](https://developer.android.com/develop/devices/assistant/intents-assistant-nav-app)：地点搜索、导航、候选消歧、停止和恢复导航、播报控制等应区分业务意图。
- [Android Automotive 地图接口](https://developer.android.com/training/cars/platforms/automotive-os/android-intents-automotive)：坐标用于模糊地点搜索偏置，途经点按顺序表达，行中搜索与普通附近搜索语义不同。
- [高德 POI 搜索](https://developer.amap.com/api/webservice/guide/api/search/)：city 默认只是城市偏置，citylimit 才严格限定；周边搜索使用中心点、半径、类型、距离排序。周边半径最大 50 km。
- [高德 PoiSearchV2.Query](https://a.amap.com/lbs/static/unzip/Android_Map_Doc/Search/com/amap/api/services/poisearch/PoiSearchV2.Query.html)：火车站等特殊 POI 可能受人工干预排序，不能假设供应商第一条就是最近结果。

据此，本项目的业务划分和边界如下（并非所有业务均已实现）：

| 业务 | 例子 | 处理策略 |
| --- | --- | --- |
| 明确目的地 | 导航到北京南站 | 保留明确地名及跨城意图，不套用泛称车站的距离限制 |
| 附近类别 | 火车站、最近的高铁站 | 先取得本轮车辆定位及当前城市，再搜索、过滤和排序 |
| 多个候选 | 第二个、成都东站 | 延续现有候选 ID、任务版本和确认流程，不重新解释为全国搜索 |
| 多途经点 | 先到火车站，再到天府机场 | 保留口述顺序；任一站解析不可靠则整条路线不执行 |
| 收藏地点 | 回家、去公司 | 应查询用户已保存的地址；未知时询问，不能让模型猜坐标（后续能力） |
| 行中变更 | 沿途找充电站、加途经点、避开高速 | 需要真实路线与导航 SDK 状态；当前 URI 交接不代表已拥有这些能力 |
| 导航控制和查询 | 停止导航、剩余多久、静音 | 需要地图 SDK 或车机接口回执，不能以本应用候选状态代替实际行程状态 |
| 定位或搜索失败 | 未授权、定位过旧、无附近车站 | 提示确认定位或说出具体城市和站名，不自动使用异地结果 |

### 确认的代码缺口

旧实现到上传协程完成连接后才读取定位，未在 VAD 开始冻结位置；当前位置只通过提示词让模型传给工具，缺少请求级强制绑定。火车站周边搜索失败时可能先走无城市限制的文本回退，逆地理编码得到的城市也未始终传到后续 geocode。原距离上限为 200 km。多站解析把上一站直接设为下一站搜索中心。解析失败仅返回提示词，随后仍可能被模型的 navigate 动作绕过。

这些是代码路径中确认的问题；尚未通过本次真机请求日志确认用户失败轮次具体经过了哪条路径。

### 本次实现

- SpeechStart 同步保存本轮有效位置，随现有 audio_start 经纬度字段上传；连接等待和同轮后续 VAD 段不改写快照。VAD 也触发有时限的定位刷新，重复段不重启正在进行的刷新。定位尚未成功时本轮保持未知，不等待 GPS 阻塞语音。
- DeepSeek 与 Qwen Omni 都从本轮 SessionContext 注入 resolve_navigation.location，覆盖模型误填坐标；本轮无定位时删除模型提供的坐标，不继承前轮位置。
- 启用 resolve_navigation 时，模型直接调用 navigate 会收到需先解析地点的工具错误；成功搜索后的候选/多站路线由既有确定性逻辑生成。
- 泛称火车站先做逆地理编码，再周边搜索。使用火车站类型、50 km 半径和距离排序（仅发送工具 schema 支持的参数），请求最多 25 个结果，再由服务端计算球面距离排序并过滤超过 50 km 的候选。
- 仅在已知当前城市时使用文本搜索或补坐标；城市一直传到 geocode。直辖市 city 为空数组时使用 province。周边工具仍可在城市解析失败时按真实中心点搜索，最终仍受距离过滤。
- 排除可识别的酒店、公交、地铁、停车场等非车站主体。已有坐标和缺失坐标混合返回时，先补充后排序，避免直接丢掉更近车站。名称过滤是启发式，不代表确认了客运运营状态。
- 所有无地域限定的多站类别默认相对本轮车辆位置；口述先后顺序不再隐式切换搜索中心。明确“前一站附近/沿途”的语义需要后续单独建模，不能由顺序猜测。
- 任一目的地无可信候选直接返回补充信息提示，终止本轮导航工具循环，既不打开部分路线，也不让模型重新猜坐标。

“最近”目前指召回到的合格候选中的球面距离最近，不是驾车时间最短。50 km 是本次泛称车站的保守产品边界；范围内无可信结果会要求明确站名，不静默扩大至全国。手机系统定位与高德坐标系的统一转换仍需后续明确，可能影响相邻地点的精细排序，但不应靠放大搜索范围解决。
