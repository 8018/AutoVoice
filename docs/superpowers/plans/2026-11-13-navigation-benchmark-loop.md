## 第 1 批：固定基准并修复四项搜索问题

保留 2026-11-13 首轮 23 条结果作不可覆盖基线。固定输入、每步动作及内容约束；自动检测候选坐标/城市范围/目标名称、只读、否定、取消、换批和站点顺序。能力不足的正确反馈单独统计，不计成功导航功能。错误、超时、缺测、语义失败均使验证失败。每次结果按时间及版本另存，附逐条变化和延迟分布。基准自身用故意错误回复测试，CI 必跑离线判定器；真实 dev 回归使用设备认证，不要求公开 PR 持有密钥。

初始性能阈值为工程默认：完整套件平均 <= 2500ms、P95 <= 5000ms，且成功目标不能通过快速拒绝变绿。首轮小样本只作比较，不当生产 SLO。修复后至少完整跑一轮，并复测四个问题；每次功能发布重复完整基准。后续用更多样本收紧阈值，禁止修改输入或放宽目标掩盖失败。

## 第 3 批：混合来源地址的多站行程

D02 当前拒绝 GPS 常用地址与地图 GCJ 地点混用。保留逐站坐标身份，确认后通过已有官方路线服务转换；校验请求身份、数量、顺序及原有 GCJ 点，完成前可取消。修改常用地址、替换语音/文本任务、模式切换和断线使旧响应失效。失败不打开未转换 URI，预览不启动。追加 D02 正常/失败/边界/多轮端侧用例和 3 项真实路线 API 基准，原文本与统计基准继续跑。

## 第 4 批：精确地点相关性与机场简称

调查发现 Search.parse 会剥离连写城市前缀，使“北京南站”变为“南站”，“上海博物馆”变为“博物馆”，混入干扰地点。新机场精确匹配还会在无显式城市时拒绝“虹桥机场”对应的“上海虹桥国际机场”。第3批全绿后修复：完整专名与明确类别搜索分开；在候选截断前核验专名/明确分馆；换批保持目标，不能用无关地点凑数；机场简称必须由同一 POI 详情中的真实城市前缀或已登记别名核验，不能任意后缀匹配。追加专名、类别、简称、精确库存耗尽、城市纠正用例，再跑全部基准。
