# 导航任务 4 行程草稿

## 行程流程

- 服务端对多地点保留原顺序，每站保留最多三个合格候选。存在多个候选的站点逐站选择，任何一站为空都会阻止交接。应用只在最后一次确认后生成原有高德路线规划 URI，最后一站为终点，其他站按原顺序成为途经点。
- 草稿展示、歧义选择、最终确认和放弃走实际导航界面。文字输入和能提供识别文本的语音链路也可确认、放弃或选择。选择、确认和放弃使用已显示草稿的任务版本，旧点击或同轮回复重复不会修改当前草稿。
- 新客户端将旧服务端已解析的多地点 `navigate + waypoints` 视为待确认草稿。新版网关在 1.2 握手后才下发 `draft_trip`，对旧版客户端提示更新。共享样例包含中间站歧义和常用地址符号引用。
- 家和公司从设备本地读取。尚未设置或确认时数据已变更，应用要求重新规划。当前路线草稿最多五站，超出时提示缩减。高德单点 URI 明确区分 `dev=0` 和 `dev=1`。

## 验证

- 客户端 RED 复现旧多点回复自动开图，以及新草稿意图未被接收。
- 服务端 RED 复现了多地点自动选首项、把常用地址当成普通 POI、以及旧客户端收到新草稿动作。
- 已用 Draft 2020-12 验证网关消息与意图。另解码 `stops` JSON 验证内层结构，并确认超出站点上限、纬度越界、同时携带候选和常用地址引用都被拒绝。

## 待验收

- 真机确认高德地图打开后实际显示的站点顺序、失败提示和反馈延迟。[高德 Android 路线规划 URI 文档](https://lbs.amap.com/api/amap-mobile/guide/android/route)
- 多地点草稿暂不使用 WGS84 常用地址。用户可在设置中为该地址选取地图地点，获得同一坐标体系的坐标。
- 逐站消歧需要新服务端发送每站的备选。旧服务端下发的单个已选地点无法恢复未传输的备选，但仍要经过整条草稿确认。
- 语音跟进依赖 ASR 转写。单独运行且不返回识别文本的语音到语音后端可使用界面或文本确认。
